# 실행한 검증과 아직 실행하지 않은 검증

2026-11-04, Node.js 24.19.0에서 확인했다. **테스트 통과는 사용자 계정에 Supabase를 배포했거나 실제 크롬북에서 검증했다는 뜻이 아니다.**

## 1.2.0 배포·활동 범위 후속 검증

- Chrome이 노출한 카메라·파일·설정 내부 주소의 개인정보 경로 제거·고정 이름·서버/확장 규칙 일치 검사.
- 실제 확장 소스의 Chrome API 모의에서 카메라 활동 전송과 내부 앱 캡처 거부, 실제 Edge HTTP handler+PostgreSQL에서 카메라 이력 저장 검사. 실제 OS 앱 감지를 실증한 것은 아니다.
- 상대 경로 빌드의 OAuth 복귀 경로·데모 제외·스크립트 실패 안내, static ZIP의 버전/설정 안내 포함 확인.
- 원격 main의 최초 데모 커밋 진단 후 새 코드와 Pages 배포 워크플로 반영을 진행한다. 원격 26fec7f의 CI와 Pages artifact 게시 성공을 GitHub 웹 UI에서 확인했다. 실사이트 HTML 직접 요청은 여전히 차단되어 별개다.

## 로컬 자동 검증

| 명령/범위              | 결과                                                             |
| ---------------------- | ---------------------------------------------------------------- |
| `npm test`             | 20개 파일 144건 통과: 운영 코드 101건 + 이전 시연 코드 회귀 43건 |
| `npm run test:legacy`  | 원격 저장소에서 보존한 최초 프로토타입 Node 테스트 12건 통과     |
| `npm run build`        | TypeScript 검사 + Vite 정적 빌드 + 선택적 CNAME 복사 통과        |
| Deno `check`           | Edge Function index/handler와 npm 의존성의 Deno 타입 검사 통과   |
| 확장 JS `node --check` | background/control/setup/lock/notice/protocol 문법 검사 통과     |
| `npm audit`            | 실행 시점 보고된 취약점 0개                                      |

보안 검증 결과는 [공격 시뮬레이션 보고서](security-review.ko.md)에서 재현·수정·잔여 위험·실서비스 미검증을 구분한다. 보완 후 테스트 통과가 유효 토큰 탈취·배포 코드 침해까지 차단했다는 뜻은 아니다.

개인 프로젝트 방식의 추가 검증:

- 연결 설정이 없으면 기본 Supabase를 사용하지 않음. 브라우저 공개 설정 저장·해제·손상 처리·비밀키 거부.
- 다른 탭에서 연결 설정을 바꿔도 현재 수업의 클라이언트·ZIP 대상은 기존 프로젝트에 고정됨.
- 프로젝트 A/B 전환 후 ZIP이 각 서버 주소만 포함하고 공개 키·로그인 토큰을 포함하지 않음.
- 연결 해제 시 현재 로컬 로그아웃·자동 갱신 중단·연결값 제거·기존 학생 화면 제거.
- ③ 소유자 SQL의 반복 적용, 기존 공용 회원도 소유자가 아니면 가입·조회·제어 불가, 소유자는 가입과 학생 명령 수신 가능.
- 최종 Edge API가 교사 회원뿐 아니라 개인 프로젝트 소유자도 확인함.
- 이전 공용 모델의 테스트는 ①② 업그레이드 회귀 검증으로 보존하고 이어서 ③ 최종 소유자 정책을 검증함. 실제 개인 Supabase 계정 배포·Google OAuth는 별도 미실행.

이전 변경에서 추가한 회귀 검증:

- Chromium 빌드 화면에서 첫 방문 Supabase 안내·교사/학생 안내 전환·닫기 후 새로고침 시 안내 반복 없음·가상 학생 0개·브라우저 예외 없음을 확인했다. 390px/1440px에서 가로 넘침이 없었다.
- 첫 방문 안내 자동 표시·닫기·재방문 상태, 로그인 전 Supabase/크롬북 안내 열기, 교사 가입 안내 확인 후 서버 RPC·대시보드 진입.
- 가입한 두 교사의 학급·학생·방문 기록·명령·최신 명령 view·캡처 메타데이터·Storage 객체를 RLS로 분리하고 교사 간 수정·승인·폐기·명령·소유권 변경을 차단.
- 교사 가입이 최고 관리자 승격으로 이어지지 않고 중지된 회원이 재가입으로 활성화되지 않음.
- Edge 서비스 권한으로도 다른 교사의 코드/복구 발급을 차단하고 캡처·코드·기록 정리를 자기 소유 학급 목록으로 제한.
- 기존 단일 관리자 학급의 소유자 이전과 반복 적용의 권한 보존.

운영 테스트의 내용:

- 빌드 결과를 Chromium에서 열어 설정 미입력 안내와 가상 학생 카드 0개를 확인했다. 화면 너비 390px/1440px에서 가로 넘침이 없었다. 실제 로그인 후 대시보드 실서비스 검증은 아니다.
- 인증 미설정·비로그인·미가입 교사 접근 차단, Google OAuth 호출, 무효 세션 처리, 빈 DB 화면, 학급 생성의 서버 RPC 호출.
- UI가 queued/delivered를 잠금 성공으로 표시하지 않고 Realtime 갱신의 applied ACK 후에만 적용 표시.
- PGlite의 실제 PostgreSQL 엔진에서 기본 SQL 2회 후 교사 업그레이드 SQL 2회 실행, RLS·RPC 실행 권한·최고 관리자 자동 승격 차단·교사 가입·교사별 소유권·승인 전 기기 제한·등록 중복·폐기.
- 다른 학생 명령 ACK 위조 차단, 같은 request ID 중복 방지, 최신 해제 우선, 오래된 명령 만료, 기록 OFF와 제어 분리.
- private 버킷 설정 및 소유 교사/유효 메타데이터를 요구하는 Storage 객체 RLS. PGlite 테스트의 storage/auth 테이블은 Supabase API의 필요한 경계를 모사한 테이블이며 호스팅 Storage/Auth 서버 자체는 아니다.
- 실제 Edge HTTP handler와 PostgreSQL RPC를 연결한 등록 → pending → 교사 승인 → 공지 → ACK → 실제 행으로 방문 저장 → 도움 요청 테스트.
- 교사별 20/50/99명 가상 기기 등록·일괄 명령 생성, 교사당 100번째 등록 거부와 다른 교사의 추가 등록 허용. **교내 네트워크 99대 부하 테스트가 아니다.**
- URL 개인정보 제거·입력/스트림 크기·JWT/기기 인증 구분·등록 빈도·교사 권한·등록/캡처 오류 입력.
- 워커 실제 소스에 Chrome API 모의를 연결하여 pending/secret 비노출·잠금 창·lease 안전 해제·도움 요청·확장 전용 공지 창·표시 확인 후 ACK·창 생성 실패 ACK·시크릿 탭 제외 검증.
- 프로토콜의 시각 역전·서버 clock 차이·revision 역전·비상 hold·절전/재시작 체류 누적·256비트 비밀 생성.
- ZIP 파일 목록·manifest/CSP·서버 주소만 포함하는 공통 구성·잘못된 URL 거부.

| 항목                                              | 현재 상태                                      |
| ------------------------------------------------- | ---------------------------------------------- |
| 사용자 Supabase 프로젝트 SQL 적용                 | 사용자 프로젝트/인증이 제공되지 않아 미실행    |
| 실제 Google OAuth·자동 로그인·교사 회원가입       | 코드/설정 안내 작성, 실제 계정 검증 미실행     |
| 호스팅 Edge Function 배포 및 Storage HTTP 업로드  | 코드·Deno 검사 완료, 사용자 서비스 배포 미실행 |
| Supabase Realtime·세션 만료·Storage 실서비스 권한 | 로컬 정책/호출 검증, 실제 서비스 통합은 미실행 |

| 실제 크롬북 잠금·캡처·절전·비상 복구              | 미실행, CHROMEOS.ko.md의 통과 기록 필요        |
| 운영 지연·실패율·99대 동시 연결·무료 사용량       | 미측정                                         |
| 자동 예약 보존 기간 정리                          | 미설정. 관리자 수동 정리 경로만 구현           |

이 클라우드의 Chromium에서 이전 단계에 확장 로드를 시도했을 때 `Loading of unpacked extensions is disabled by the administrator.`로 차단되었다. 해당 정책을 우회하지 않는다. Chrome API 모의 테스트가 실제 설치 성공의 증거는 아니다.

실제 사용을 시작하기 전 [설치 안내](SETUP.ko.md)를 적용하고 [실기기 검증표](CHROMEOS.ko.md)를 확인한다. 운영 기본 모드에는 시연 데이터가 없으며 외부 설정이 없으면 연결 설정 화면을 표시한다.
