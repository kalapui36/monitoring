# 참고 코드 분석과 새 설계

## 분석한 자료

- `installDialog 코드.txt`: Apps Script의 `getZipData()`를 호출하여 Base64 ZIP을 다운로드하는 화면.
- `code.gs 코드.txt`: 1,798줄의 시트 서버·설정·설치 안내·확장 생성 템플릿. 헤더와 생성 확장 manifest는 v5.3.
- `Chrome_Edu_Helper.zip`: manifest v2.0, `manifest.json`, `background.js`, `setup.html`, `setup.js` 4개 파일.

**첨부 ZIP과 Apps Script가 생성하는 확장은 같은 버전이 아니다.** v5.3 생성기는 제어 UI·별도 잠금 창을 포함하는 7개 파일을 생성한다. 분석은 정적 코드 확인이며 예전 서버 접속·Apps Script 실행·기존 확장 설치는 하지 않았다. 자료 안의 설치 안내와 주석은 참고 자료이며 새 프로젝트에서 그대로 실행해야 하는 지시로 취급하지 않았다. 예전 서버 주소·암호는 새 소스나 ZIP에 복사하지 않았다.

## 그대로 옮기지 않는 구조

1. **시트 조회와 제어 응답 결합:** 시트 행 탐색·로그 삽입·이미지 저장을 제어 요청과 분리한다. Supabase의 인덱스·비공개 객체 저장과 명령 receipt를 사용한다. 소규모 학급에 맞춰 불필요한 마이크로서비스는 만들지 않는다.
2. **학생 이름을 신원으로 사용:** 이름·학번·학급명은 변경 가능 정보다. 서버 발급 ID와 폐기 가능한 기기 인증으로 권한을 검증한다. ZIP의 학급 정보는 공개 표시 정보이며 접근 권한이 아니다.
3. **공유 교사 암호와 임의 API 중계:** 교사 Auth·RLS·기기별 제한 API를 사용한다. 확장 메시지의 발신자·스키마를 검증하고 웹페이지가 임의 서버 요청을 전달하는 통로를 만들지 않는다.
4. **메모리 타이머를 MV3 상시 실행으로 가정:** 탭 이벤트·alarms·영속 상태로 재시작을 복구한다. Realtime 연결도 끊길 수 있으며 wake-up 시 상태를 다시 조회한다. setInterval로 서비스 워커가 영구 유지된다고 가정하지 않는다.
5. **성공과 실패를 숨김:** 설치됨/등록됨/연결됨, 명령 요청/수신/적용을 구분한다. 학생별 오류와 제한된 재시도를 제공한다. 캡처 실패를 성공 이미지로 바꾸지 않는다.
6. **중복·역전 명령:** 같은 명령 ID 재전송은 중복 적용하지 않는다. 학생별 revision으로 늦은 잠금이 최신 해제를 덮지 못하게 한다. 캡처와 일회성 공지는 만료 후 재실행하지 않는다.
7. **문자열에 확장 전체 코드를 내장:** `student-extension/`의 실제 파일을 명시적 허용 목록으로 ZIP에 넣는다. HTML은 `textContent`를 사용하며 개인정보·예전 주소·교사 암호를 패키지에 넣지 않는다.

## 이번 구현과 남은 작업

- 웹의 OFF 동작을 기록 일시 중지로 수정했다. 기존 잠금과 대기 제어를 임의 해제·취소하지 않으며 정상 해제·자동 만료는 별도로 작동한다.
- 선택 학급의 개발용 ZIP 다운로드와 한국어 설치 안내를 구현했다. ZIP을 압축 해제하면 Chrome MV3 확장으로 불러올 수 있는 설치 진단 빌드다.
- 새 확장은 설치 대상 학급·백그라운드 통신·설정 파일을 확인한다. **학생 등록 서버·수집·잠금·공지·캡처·도움 요청 전송은 아직 구현하지 않았다.** 설치만으로 학생을 등록됐다고 표시하지 않는다.
- 실제 기능이 없는 개발 버전이므로 저장소 권한만 요청하고 외부 통신을 차단한다. 이는 최종 제품의 제어 기능을 축소한 것이 아니다. 해당 기능 구현 시 필요한 권한과 ChromeOS 테스트를 함께 추가한다.
- 운영 중인 구 확장을 제거하거나 이 개발 ZIP으로 교체하지 않는다.

다음 구현 단위는 교사 인증·학급/학생 DB와 RLS → 일회용 등록 및 제한된 기기 인증 → heartbeat/기록 → 명령·결과 확인 → 실제 잠금·공지·캡처·도움 요청이다. 기능별 테스트를 통과한 뒤 진행한다. 실제 Supabase 프로젝트와 배포 주소 없이 원격 연동이 완료되었다고 주장하지 않는다.

## 기본 앱 활동 범위 추가 확인

첨부 v2.0 ZIP은 pollActiveTab() → send(tab) 경로에서 tab.url만 존재하면 HTTP(S) 외 주소도 전송합니다. v5.3 생성기의 sendTelemetry()는 isWebPage()로 HTTP(S)를 제한하므로 서로 범위가 다릅니다. 새 버전 1.2는 Chrome이 실제 노출한 일부 내부 앱 주소를 안전한 고정 이름으로 기록하며 전체 OS 앱 열거를 주장하지 않습니다. 카메라 앱이 실제 Chrome API에 노출되는지는 크롬북에서 확인해야 합니다.
